Agent-4：UnrealMCP —— Agent 如何触达 UE 编辑器

对应代码：shared/mcp_client.py、agents/assetsage.py；UE 侧是 RaidGame/Plugins/UnrealMCP 原生插件
UnrealMCP = 在 UE 编辑器里开一个 TCP 服务，把引擎能力包成「命令」，Agent 发 JSON 就能查询和操作编辑器。

1. 三层结构

图 1：Python Agent 通过 TCP 命令协议驱动 UE 原生插件

2. 为什么是 TCP + JSON 命令，不是直接 Python 脚本

方案问题
Agent 生成 UE Python 脚本任意代码执行，不可控、难验证
命令协议（本项目）能力边界固定，每个命令有明确参数和返回，可白名单、可测试

3. 客户端的四个设计取舍

  1. 短连接：一次请求一个 socket。服务端是单客户端串行执行，短连接最省心，不用管连接状态。
  2. 永不抛异常：连不上 / 超时 / 非法 JSON，一律返回 {"status":"error","error":"..."}。错误变成 observation，让 LLM 自己决定停还是换方向。
  3. 边收边判完整：协议没有长度头，所以每收一块就试 json.loads，成功就返回；超时但已有数据也返回，不死等。
  4. 先 ping 再干活：client.ping() 探测一次，失败就在 prompt 里警告 LLM「服务不可达，建议直接 finalize」。

4. 编辑器未启动时（优雅降级）

图 2：整个系统不会因为 UE 没开而崩溃

5. 读与写

  • 读：get_asset_info（Nanite / LOD / 材质 / 面数）、get_visible_static_mesh_actors、scan_actors_for_component… 用来定位问题。
  • 写：修改编辑器中资产属性来修复问题，走的是同一个 call(command, params) 通道，区别只在命令本身。
  • 闭环：读 → 判断 → 写 → 再读回验证，写完必须回读确认生效。
仓库里 AssetSage 的 _TOOL_MAP 目前只放了 6 个只读命令；写命令的白名单、回读验证请按你实际实现补充到这里。

6. 你该记住的 3 件事

  1. MCP 的本质：把引擎能力变成有边界的命令，Agent 只能在边界内行动。
  2. 客户端要不抛异常、有超时、能判断响应完整，错误当作 observation 还给 LLM。
  3. 修改类能力一定配回读验证，否则「改了」不等于「生效了」。
