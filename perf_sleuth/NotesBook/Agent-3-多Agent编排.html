Agent-3：多 Agent 编排 —— Planner / State / Handoff

对应代码：graph.py、state.py、agents/planner.py
多 Agent = 一个共享 State + 一个 route 指针 + 一个 while 循环轮流让谁上场。

1. 为什么要拆成多个 Agent

Agent工具集数据源为什么分开
Plannerhandoff / finalize无只做判断和汇总，prompt 短而稳
CodeSage4 个源码工具SQLite + ripgrep静态知识，永远可用
AssetSage6 个 MCP 工具UE 编辑器活数据依赖编辑器，可能不可用

工具少，LLM 选错概率就低；一个 Agent 一类数据源，故障也被隔离在自己那一层。

4. 两条路由：规则优先，LLM 兜底

  1. 规则强制路由：detect_forced_agent 匹配「查资产 / 查代码 / nanite / grep…」关键词，命中直接 handoff，不花 LLM 调用。资产关键词优先（更具体）。
  2. LLM 路由：规则没命中，才让 Planner 的 LLM 在 handoff_codesage / handoff_assetsage / finalize 里选；拿不准先派 CodeSage（源码永远可查）。

5. 一次会话实际走几轮：3 轮，只派一个专家

重要更正：graph.py 文件头的注释和 README 都写了「Planner 可以多轮 handoff，先派 CodeSage 再派 AssetSage 验证」，但当前代码做不到。拦路的是 planner.py 第 109 行： 
if state.findings:          # 只要 findings 非空
    return _summarize(...)  # 就直接汇总，route = done
也就是说：Planner 一看到有 findings，立刻收尾，不会再 handoff 第二个专家。所以一次会话最多用到一个专家 Agent。
图 3（已按真实代码更正）：turn 2 是「二选一」，不是「先代码再资产」

想让两个专家合作，要改什么

  1. 改 planner.run 的入口判断：把 if state.findings: return _summarize(...) 去掉，改成每次都让 LLM 在「继续 handoff / finalize」之间选。
  2. 汇总 prompt 要带上选项：_summarize 目前只要求输出 finalize，需要新增「再派 AssetSage」这类动作。
  3. graph 层要认新 route：目前 route 回到 planner 后，下一轮由 Planner 决定；只要 Planner 能再写 route="assetsage"，graph 已经支持，不用改。
好消息：改动集中在 planner.py 一处。graph.py 的 while 循环本来就是为多轮设计的，只差 Planner 不再「见好就收」。

6. 你该记住的 3 件事

  1. State.route 是外层循环的「行动指针」，子 Agent 只改 route 和写 findings，不直接互相调用。
  2. Agent 要少工具、单数据源，故障隔离、prompt 简单。
  3. 规则路由省 LLM 调用且可控，LLM 路由负责模糊问题。
