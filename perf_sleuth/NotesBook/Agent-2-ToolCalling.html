Agent-2：Tool Calling —— LLM 怎么「准确」调函数

对应代码：codesage.py / assetsage.py 的 TOOLS_DOC、_exec_tool；llm.py 的 chat_json
LLM 不会真的「调用」函数，它只会输出一段 JSON；真正执行函数的是你的 Python 代码。

1. 整条链路（先看图）

图 1：一次 Tool Calling = 说明书 → JSON 决策 → 解析 → 白名单派发 → 结果回灌

2. 四个关键点

① 说明书（TOOLS_DOC）决定 LLM 会不会用对

说明书写在 system prompt 里。每个工具必须写清：用途 / 参数名 / 返回结构 / 易错点。

2. get_asset_info
   参数: {"asset_path": "/Game/xxx/SM_Foo.SM_Foo"}
   **重要**: 必须是 ObjectPath，末尾要重复资产名     ← 把踩过的坑直接写进说明书

② 输出格式：固定一个 JSON 形状

{"thought": "这步想拿什么证据", "tool": "工具名", "args": {...}}
手段代码位置作用
"format": "json"llm._post_ollama让 Ollama 强制输出 JSON
temperature = 0chat_json决策要稳定，不要发散
num_ctx = 8192_post_ollama默认 2K 会被工具输出撑爆

③ 解析：宽进严出

图 2：_extract_json 两级兜底 + chat_json 一次重试

④ 派发：白名单 + 参数矫正

  • 白名单：_TOOL_MAP 里没有的工具名，直接返回「未知工具」，LLM 编不出新命令。
  • 参数矫正：_normalize_args 把 LLM 常写错的参数名自动改对（directory → path、component_class_name → component_class），省掉一轮白跑。
经验：LLM 总会犯同一类错 → 与其反复改 prompt，不如在代码层兜住（矫正、白名单、去重）。

3. 你该记住的 3 件事

  1. Tool Calling = 「说明书 + JSON 约定 + Python 派发」，LLM 只负责选。
  2. 输出必须可解析：format=json + 提取 + 一次重试。
  3. 入口要白名单，常见错误在代码层矫正。
